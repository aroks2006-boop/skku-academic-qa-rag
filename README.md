# SKKU 학사 Q&A RAG

성균관대 학사·졸업요건 질문에 학칙·학사제도 안내 문서(스캔본 184쪽 포함)를 **근거로** 답하는 RAG 도구.
학교 챗봇(킹고봇)과 일반 LLM을 사람이 검수한 정답셋으로 자동 채점해 비교했다.

## 한눈에 보기

| | RAG (이 프로젝트) | 일반 LLM | 킹고봇 |
|---|---|---|---|
| 정답률 (49문항) | **89.8%** | 10.2% | 7.5% |
| 정답률 (튜닝에 쓰지 않은 새 19문항) | **89.5%** | 0.0% | 10.5% |
| 문서에 없는 질문에 지어낸 답 | **0건** | 있음 | - |

- **문제:** 학사 규정은 수백 쪽 문서에 흩어져 있고 학번·학과별 조건이 복잡하다. 킹고봇은 문장형 질문 49개 중 46개에 답하지 못했다(키워드 매칭 방식)
- **해결:** 스캔본 OCR → 표 구조를 살린 인덱싱 → 하이브리드 검색 + LLM 재정렬 → 근거 페이지를 밝히는 답변
- **검증:** 정답셋 68문항을 AI가 원본과 1차 대조한 뒤 사람이 전수 검수. 단계별 비교 실험으로 각 개선의 기여도를, OCR 모델 3종 비교로 모델 선택 근거를 측정
- **판단:** 웹 검색 기능은 시험해 보니 엉뚱한 페이지를 인용해 도입하지 않음. OCR은 3배 느려도 표 정확도 100%인 모델을 채택
- **비용:** 질문당 약 $0.003(4원), 응답 2.5초

### 개발 방식
Claude Code(AI 코딩 도구)로 구현했다. 문제 정의와 비교 대상(킹고봇) 선정, 평가 설계, 정답셋 검수, 실험 결과 해석과 방향 결정(웹 검색 미도입, 실시간 정보 확장 설계 등)은 직접 했다.

## 결과 (2026-11-14, 49문항, 채점 3회 반복)

| 시스템 | 정답률 | 부분정답 포함 | 근거있는 46문항 정답률 | 회피율 |
|---|---|---|---|---|
| RAG (gpt-4.1-mini) | **89.8%** | 95.2% | 89.9% | 0% |
| 일반 LLM (gpt-4.1-mini, 검색 없음) | 10.2% | 21.8% | 10.9% | 0% |
| 킹고봇 (첫 응답 기준) | 7.5% | 7.5% | 4.3% | 89% |

- 채점 모델(gpt-4.1-mini, temperature 0) 3회 반복: RAG·일반 LLM 편차 0.0%p, 킹고봇 ±1.0%p(6.1~8.2%). 실행을 따로 돌리면 문항 1개(±2%p) 정도 차이가 날 수 있음
- 정답셋 49문항: AI가 원본 페이지 이미지·조항과 1차 대조(숫자 오류 없음)한 뒤, 사람이 전 문항을 원본과 대조해 최종 확인함. 판단이 필요했던 3문항(q022, q038, q044)은 정답 문구를 수정
- 킹고봇 49문항 응답 유형: 사과 문구 29, 추천 질문 목록 7, 모름 6, 메뉴 선택 4, 직접 답변 3 (`eval/kingobot_answers.csv`의 `response_type`)
- 킹고봇은 추천 질문·메뉴를 클릭하지 않은 첫 응답 기준. q047(기숙사)은 킹고봇이 별도 지식으로 맞게 답했지만 "문서 근거 없음" 문항이라 오답 처리됨 → 근거있는 46문항 정답률을 함께 볼 것
- 이전 구성(gpt-4o-mini, 마크다운 표 그대로 인덱싱) 결과: RAG 79.6%, 일반 LLM 18.4% → `eval/answers/gpt-4o-mini/`

### 새 문항 재평가 (튜닝에 쓰지 않은 19문항, `eval/heldout.jsonl`)

| 시스템 | 정답률 | 부분정답 포함 |
|---|---|---|
| RAG | **89.5%** | 94.7% |
| 일반 LLM | 0.0% | 10.5% |
| 킹고봇 | 10.5% | 10.5% |

- 개선 과정에서 한 번도 보지 않은 페이지(증명서, 현장실습, 교직, 초과등록 등)에서 출제. 기존 49문항(89.8%)과 같은 수준이라 특정 문항에 과적합되지 않았음을 확인
- RAG 오답 0건, 부분정답 2건(부수 조건 누락)
- 정답 19문항 모두 AI 1차 대조 후 사람이 원본과 대조해 최종 확인

### 단계별 비교 실험 (49문항, 채점 모델 gpt-4.1-mini 고정, `eval/ablation.py`)

| 구성 | 정답률 | 부분정답 포함 | 평균 응답시간 | 질문당 비용 |
|---|---|---|---|---|
| 1. 벡터 검색 + 마크다운 표 + gpt-4o-mini | 73.5% | 81.6% | 1.8초 | $0.0002 |
| 2. + 하이브리드(BM25) 검색 | 67.3% | 79.6% | 2.1초 | $0.0003 |
| 3. + LLM 재정렬 | 75.5% | 85.7% | 3.2초 | $0.0009 |
| 4. + 표를 행별 `열: 값`으로 풀어쓰기 | 79.6% | 87.8% | 2.9초 | $0.0010 |
| 5. + 답변 모델 gpt-4.1-mini | 81.6% | 90.8% | 2.4초 | $0.0027 |
| 6. + 표 읽기·조항 우선 규칙 (최종) | **85.7%** | **92.9%** | 2.5초 | $0.0028 |

- 표 풀어쓰기(3→4)로 넓은 표 문항(q006 수료학점, q009 수강학점)이 오답에서 정답으로 바뀜
- 하이브리드 검색 단독(2)은 정답률이 오히려 낮았지만, 재정렬과 결합(3)하면 검색 후보가 넓어져 이득. 검색 지표(MRR)는 0.62→0.90으로 상승
- 최종 구성의 질문당 비용은 약 $0.003(4원), 응답 2.5초. 같은 구성을 본 평가(89.8%)와 따로 실행해 생긴 차이(문항 2개)는 LLM 생성·채점 편차

### OCR 모델 비교 (표 11쪽 핵심 칸 57개, `eval/ocr_eval.py`)

| 모델 | 핵심 칸 정확도 | 실패한 쪽 | 쪽당 시간 |
|---|---|---|---|
| gpt-4o-mini | 52.6% (30/57) | 0 | 8.9초 |
| gpt-4.1 | 80.7% (46/57) | 1 (출력 반복 폭주) | 9.7초 |
| **gpt-5-mini (채택)** | **100% (57/57)** | 0 | 30.3초 |

- 핵심 칸: 원본 이미지에서 사람이 확인한 (행 이름, 값) 쌍이 OCR 결과의 같은 줄에 있는지로 판정
- OCR은 1회만 수행하고 캐시하므로 속도보다 정확도를 우선

### 한계
- 정답셋은 OCR 텍스트를 근거로 작성했다. OCR 텍스트에는 작은 오류가 남아 있을 수 있다(예: p.78 '건축토목공학부'가 '건축도시공학부'로 인식됨)
- 셔틀버스·식단표·기숙사 일정처럼 학교 홈페이지에만 있는 정보는 답하지 않는다(근거없음 문항). OpenAI 웹 검색으로 시험해 보니 관련 페이지는 찾지만, 셔틀 질문에 캠퍼스 간 셔틀 대신 혜화역 셔틀 정보를 답하거나 2023년 페이지를 근거로 쓰는 등 정확도가 낮았다
- 표 처리·프롬프트 개선은 같은 정답셋의 오답을 보며 진행했으므로 수치가 다소 낙관적일 수 있다

## 실행 방법 (Windows)

필요한 것: Python 3.11 이상, OpenAI API 키, 학교 문서 PDF(저작권 문제로 저장소에 없음)

1. 학교 홈페이지에서 「2026 학사제도 안내」, 학칙, 학칙시행세칙 PDF를 받아 `data/raw/`에 넣기
2. **`setup.bat` 더블클릭** (최초 1회): 패키지 설치 → `.env`에 API 키 입력 → 문서 인덱싱(스캔본 OCR 포함 20~40분, 약 $3)
3. **`run.bat` 더블클릭**: 앱이 뜨고 브라우저가 자동으로 열림. 끝내려면 검은 창을 닫기

바탕화면에서 바로 열려면 `run.bat` 우클릭 → 바로 가기 만들기 → 바로 가기를 바탕화면으로 옮기기

명령어로 실행하려면:
```
pip install -r requirements.txt
copy .env.example .env
python ingest.py
streamlit run app.py
```
`python check_api.py`로 API 키 연결 확인, `python rag.py "질문"`으로 터미널에서 바로 질문 가능

## 구조
- `ocr.py`: 텍스트 없는 스캔 페이지만 gpt-5-mini로 OCR, 결과는 `data/ocr/`에 페이지별 캐시. 출력 과다·판독 거부 시 페이지를 3분할해 재시도
  - 학교 문서 원본과 OCR 텍스트는 저작권 문제로 저장소에 포함하지 않음. 재현하려면 학교 홈페이지에서 PDF를 받아 `data/raw/`에 넣고 `python ingest.py` 실행(OCR 비용 약 $3)
- `ingest.py`: 페이지를 표·본문·조항 단위로 나누고 청크마다 `[문서 p.N] 장 > 표/조항 제목` 머리말을 붙임. 표는 행마다 `열 제목: 값`으로 풀어 써서 넓은 표도 열을 헷갈리지 않게 함
- `rag.py`: 벡터 + BM25 하이브리드(RRF) 후보 20개를 LLM이 재정렬한 뒤 상위 5개로 답변 (`RETRIEVE_MODE=vector|hybrid|rerank`)
- `app.py`: Streamlit 채팅 UI, 답변별 근거 문서 표시
- `review.py`: 정답셋 검수 화면 (`streamlit run review.py`), 문항과 원본 PDF 페이지를 나란히 보여주고 AI 1차 대조 메모와 ⚠️ 표시를 보여줌
- `config.py`: 모델·청크·검색 설정 (`OPENAI_CHAT_MODEL`, `OPENAI_EMBED_MODEL`, `OPENAI_OCR_MODEL`)

## 평가
- `eval/questions.jsonl`: 한 줄에 한 문항 `{id, category, question, gold, keywords, source, verified}`
  - `gold`는 원문 근거로 작성, `keywords`는 정답에 반드시 들어가야 할 숫자·용어
  - `source`는 근거 파일과 PDF 페이지 번호(인쇄된 쪽번호 아님), 원본과 대조 후 `verified`를 `true`로
  - 문서에 답이 없는 문항은 `"answerable": false`: "모른다/확인 불가"라고 답해야 정답 처리
- `eval/kingobot_answers.csv`: 킹고봇에 같은 질문을 넣고 받은 첫 응답 (`id,question,answer,response_type`)
- `python eval/run_eval.py [--repeat 3]`
  - `rag`, `plain`(검색 없는 일반 LLM), `kingobot`을 LLM 채점자(correct/partial/incorrect/abstain)와 키워드 재현율로 자동 채점
  - 생성 답변은 `eval/answers/`에 캐시되어 재사용, 다시 생성하려면 해당 파일 삭제
  - `--repeat N`은 채점만 N회 반복해 평균·표준편차 출력
  - 결과는 `eval/results.csv`, 콘솔에 시스템별·카테고리별 점수 출력
- `python eval/retrieval_eval.py`: 정답 페이지가 정해진 질문(`eval/retrieval_cases.jsonl`)으로 검색 모드별 Hit@5·MRR 비교 (현재 rerank Hit@5 100%, MRR 0.900)
